---
title: How it works
description: The decision point, the files it touches, and what survives a GridPane update.
---

The decision happens in the PHP location, after GridPane has decided to skip the cache for a query
string. When the query is made only of listed parameters, the engine un-skips the request, swaps in
the clean URL's cache key, hands PHP the clean URL and re-appends the parameters to a same-host
redirect.

```text
request /about-us/?gclid=1&utm_source=x
  │
  ├─ GridPane wpfc.conf / wp-redis.conf (server):
  │      query string ≠ ""  → skip_cache=1, skip_reason="-query_string"
  │      + your own skip rules (they set/append skip_reason)
  │      + the site's flag: $gp_mkt_fcgi="<site>" (FastCGI template) or $gp_mkt_redis="<site>" (Redis)
  │
  ├─ location / → try_files … /index.php?$args   (plus any rewrites of your own)
  │
  └─ location ~ \.php$  →  marketing-params-php-context.conf  (the decision happens HERE)
        Redis only, before it: GridPane has set $key "dbN:$scheme$request_method$host$request_uri"
        un-skip only if:  the flag matching this vhost's cache type is set, and the switch
                          ($gp_mkt_sw) is of the same site and cache type
                          Redis: $key has exactly GridPane's stock formula
                          skip_reason == "-query_string" (the only reason)
                          GET/HEAD
                          $args == the original query (nothing rewrote it)
                          ≤ 2048 bytes, ≤ 24 params, ALL of them on the list
        → skip_cache=0, key …$host/about-us/  (= the clean URL's key)
             FastCGI: fastcgi_cache_key   Redis: $key and $escaped_key, same dbN: prefix
        → PHP: REQUEST_URI=/about-us/, QUERY_STRING=""
        → 3xx Location (same host) + "?gclid=1&utm_source=x"
```

## Files

| File | Context | Role |
|---|---|---|
| `/etc/nginx/marketing-params/params.list` | include in `map` | **the list you edit** |
| `/etc/nginx/marketing-params/engine.conf` | http | `map` chain, generated by `build-engine.py` |
| `/etc/nginx/marketing-params/php-context.conf` | php location | decision, clean URL for PHP, `Location` fix (shared by both cache types) |
| `/etc/nginx/marketing-params/php-context-fcgi.conf` | php location | FastCGI: `php-context.conf` plus the cache key |
| `/etc/nginx/marketing-params/php-context-redis.conf` | php location | Redis: `php-context.conf` plus the new `$key` / `$escaped_key` |
| `/etc/nginx/marketing-params/limits.env` | – | saved limits |
| `/etc/nginx/conf.d/marketing-params.conf` | http | stub: `include …/engine[.]conf;` |
| `/var/www/<site>/nginx/marketing-params-php-context.conf` | php location | **site switch**: `set $gp_mkt_sw "f:<site>"; include …/php-context-fcgi[.]conf;` (FastCGI) or `set $gp_mkt_sw "r:<site>"; include …/php-context-redis[.]conf;` (Redis) |
| `/var/www/<site>/nginx/marketing-params-skip-fcgi-cache-context.conf` | server | **FastCGI flag**: `set $gp_mkt_fcgi "<site>";` (GridPane includes this pattern only in its FastCGI template) |
| `/var/www/<site>/nginx/marketing-params-skip-redis-cache-context.conf` | server | **Redis flag**: `set $gp_mkt_redis "<site>";` (GridPane includes this pattern only in its Redis template) |

The engine only accepts a flag and a switch of the same site and the same cache type. GridPane's
add-on-domain overlays include one site's `*-php-context.conf` in another site's vhost and then set
`REQUEST_URI` again, which would hand PHP the original URL on a request that gets cached; with two
different names nothing is un-skipped there. A staging push copies the source's files over the
target's without deleting any, which can leave a flag of the other cache type next to the switch;
such a pair is ignored too, and the next install run removes the extra flag.

## Robustness

What GridPane leaves alone, and what it does not (from an audit of GridPane's scripts, gp-cli
1.2.1518 / configs 1.2.90, 2026-10-07):

- **Kept:** the nightly jobs, `gp update` (including force runs), per-site config regeneration and
  gridpane-nginx package upgrades never delete or rewrite these custom-named files. They only reset
  permissions: 640 under `/etc/nginx`, and root:root 644 in the site's `nginx/` dir, where symlinks
  are deleted, so the switch files must stay regular files. GridPane's update also strips every line
  containing certain directive names from custom files; `install.sh` refuses to ship such a line.
- **Removed or replaced:** the per-site files go away when the site is deleted, when it is fully
  restored from a backup (they return to whatever the backup held), or when another server's site is
  cloned or migrated into it. A Migrately move does not carry the server-wide engine.
- **Not under our control:** GridPane can change its own template on any update. Run
  `./install.sh --status` after GridPane updates (it checks file checksums, the running config, the
  template hooks and `nginx -t`), and re-run `./install.sh <site>` after a restore or clone.

Other cases worth knowing:

- **Clone to a server without the engine.** GridPane only copies `/var/www/<site>/nginx/`, and the
  include uses an exact-name glob. On such a server nothing happens and `nginx -t` passes.
- **Site switched to another cache type or to no cache.** The switch stays inert, because each flag
  file is only included by its own GridPane template. Run `./install.sh <site>` again to switch it on
  for the new type; `--status` lists such sites.
- **No dependency on GridPane's variables.** The engine never references them and the switches
  declare them themselves, so changing a site's cache type in the GridPane UI cannot break
  `nginx -t`, and a server without any Redis site has no `$key` at all.
- **Your own rules win.** This holds for a skip rule that sets/appends `$skip_reason` (as all GridPane
  KB examples do) and for a rewrite that changes `$args`.
- **Stray copies are ignored.** Files like `engine.old.conf` or `php-context.orig.conf` are not loaded.
  A missing `params.list` means "nothing counts as marketing".
- **Long queries cost nothing.** Above 2048 bytes (or with a path longer than 8 KB) the chain does not
  run. It also stops at the first parameter that is not on the list.
